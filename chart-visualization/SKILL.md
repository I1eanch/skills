# Выбор типа графика и подготовка данных

Скилл решает задачу, которая обычно решается наугад: **какой график уместен для этих данных и какие поля он требует**. Каталог из 26 типов, для каждого — отдельная спецификация в `references/` с обязательными и опциональными полями, значениями по умолчанию и рекомендациями по подготовке данных.

Рендер выполняется локальными средствами (см. раздел «Рендер»). Скилл отвечает за решение и за корректную структуру данных, а не за картинку.

## Порядок работы

### 1. Выбор типа

Определить характер данных и взять тип из каталога:

| Задача | Тип |
|---|---|
| Динамика во времени | `generate_line_chart` (тренд), `generate_area_chart` (накопление), `generate_dual_axes_chart` (две разные шкалы) |
| Сравнение категорий | `generate_bar_chart` (горизонтальные), `generate_column_chart` (вертикальные) |
| Распределение частот | `generate_histogram_chart` |
| Доли целого | `generate_pie_chart`, `generate_treemap_chart` (иерархические доли) |
| Связи и потоки | `generate_scatter_chart` (корреляция), `generate_sankey_chart` (поток), `generate_venn_chart` (пересечение), `generate_network_graph` (граф связей) |
| География | `generate_district_map` (регионы), `generate_pin_map` (точки), `generate_path_map` (маршруты) |
| Иерархии | `generate_organization_chart`, `generate_mind_map` |
| Многомерное сравнение | `generate_radar_chart` |
| Этапы процесса | `generate_funnel_chart` (воронка), `generate_flow_diagram` (блок-схема) |
| Процент выполнения | `generate_liquid_chart` |
| Частота слов | `generate_word_cloud_chart` |
| Статистическое распределение | `generate_boxplot_chart`, `generate_violin_chart` |
| Причины и следствия | `generate_fishbone_diagram` |
| Таблица или сводная таблица | `generate_spreadsheet` |

Правила выбора:

- **Данные диктуют тип, а не наоборот.** Если для красивого графика приходится домысливать или сглаживать числа — тип выбран неверно.
- Круговая диаграмма читаема до 5–7 сегментов; больше — столбчатая или `generate_treemap_chart`.
- Две метрики с разным порядком величин — `generate_dual_axes_chart`, а не две оси на одном графике.
- Если сравнение важнее визуального впечатления, таблица честнее графика: `generate_spreadsheet`.

### 2. Спецификация данных

Прочитать соответствующий файл в `references/` (например `references/generate_line_chart.md`) и разложить данные по требуемым полям. В спецификации указаны обязательные поля, опциональные, значения по умолчанию (`width`, `height`, `theme`) и требования к подготовке данных — например выравнивание временных точек или предварительная агрегация до дневной или недельной гранулярности.

### 3. Рендер

Спецификация передаётся локальному средству:

| Средство | Когда |
|---|---|
| `visual-explainer` | самодостаточный HTML — схемы, диаграммы, объяснения, сравнения |
| `recharts` | графики в React-проекте |
| `ckm-slides` | графики Chart.js внутри презентации |
| `data-analysis` | подготовка самих чисел из Excel/CSV перед построением |

Результат сохраняется в `_Resources/`, в отчёте или заметке на него ссылаются относительным путём.

## Ограничения

- **Внешний сервис рендеринга удалён.** В оригинале скилл вызывал `scripts/generate.js`, который отправлял данные POST-запросом на `https://antv-studio.alipay.com/api/gpt-vis` и возвращал URL картинки. Скрипт удалён: данные отчётов и выгрузок не должны уходить на сторонний эндпоинт. Поля спецификаций из `references/` при этом сохраняют смысл как контракт данных для локального рендера, но специфичные для того сервиса параметры оформления (`style.texture`, `theme: academy`) локальными средствами не поддерживаются — их можно игнорировать.
- Каталог покрывает выбор типа и структуру данных, но не вопросы вкуса: подбор палитры, типографику и композицию решают `visual-explainer` и дизайнерские скиллы.
