# generate_flow_diagram — блок-схема процесса

## Назначение
Показывает бизнес-процесс, цепочку согласований или шаги алгоритма в виде узлов и связей; поддерживает разные типы узлов — начало, условие, действие и другие.

## Входные поля
### Обязательные
- `data`: object, обязательное, содержит описание узлов и связей.
- `data.nodes`: array<object>, минимум 1 элемент; у каждого узла должно быть уникальное `name`.
- `data.edges`: array<object>, минимум 1 элемент; содержит `source` и `target` (string), опционально `name` как подпись связи.

### Опциональные
- `style.texture`: string, по умолчанию `default`, доступно `default`/`rough`.
- `theme`: string, по умолчанию `default`, доступно `default`/`academy`/`dark`.
- `width`: number, по умолчанию `600`.
- `height`: number, по умолчанию `400`.

## Рекомендации
Сначала перечислите узлы с уникальными `name`, затем задайте связи. Условия переходов описывайте в `edges.name`. Процесс должен идти в одном направлении или иметь явные ветвления — избегайте пересекающихся связей.

## Результат

Спецификация данных для локального рендера: график строится средствами `visual-explainer`, `recharts` или `ckm-slides` (Chart.js). Внешний сервис рендеринга в этой установке не используется.
