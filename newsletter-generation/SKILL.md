# Дайджесты и рассылки

Скилл собирает выпуск, который не стыдно отправить подписчикам: материалы из нескольких источников с отбором, авторский комментарий вместо пересказа и единая структура. Ориентиры формата — Morning Brew, The Hustle, TLDR, Benedict Evans.

Выход — Markdown, пригодный для email-платформы, публикации на сайте или конвертации в HTML.

## Фаза 1. Планирование

### Параметры выпуска

| Параметр | Описание | По умолчанию |
|---|---|---|
| **Тема** | о чём выпуск | обязателен |
| **Формат** | ежедневная сводка, недельный обзор, глубокое погружение, отраслевой брифинг | недельный обзор |
| **Аудитория** | техническая, руководители, широкая, узкое сообщество | широкая |
| **Тон** | профессиональный, разговорный, с иронией, аналитический | разговорно-профессиональный |
| **Объём** | короткий (5 минут чтения), средний (10 минут), длинный (15+) | средний |
| **Секции** | количество и тип блоков | 4–6; у отраслевого брифинга их 7 — структура формата приоритетнее этого значения |
| **Периодичность** | разовый выпуск или часть серии | разовый |

Если параметров не хватает — задать **один** вопрос, покрывающий все пробелы сразу, а не по одному.

### Структура под формат

**Ежедневная сводка**
```
1. Главная история (одна, подробно)
2. Коротко (3–5 пунктов)
3. Цифра или цитата дня
4. За чем следить
```

**Недельный обзор**
```
1. Вступление от редактора
2. Главное (2–3 истории, подробно)
3. Тренды и разбор (1–2, авторский комментарий)
4. Коротко (4–6 пунктов)
5. Инструменты и материалы (2–3)
6. И последнее
```

**Глубокое погружение**
```
1. Введение и контекст
2. Предыстория: почему это важно
3. Ключевые события с разбором
4. Мнения экспертов
5. Что дальше и какие следствия
6. Что почитать
```

**Отраслевой брифинг**
```
1. Краткая сводка для занятых
2. Рынок
3. Новости компаний и кадровые движения
4. Продукты и технологии
5. Регулирование
6. Данные и метрики
7. Прогноз
```

## Фаза 2. Сбор и отбор материалов

Качество выпуска напрямую зависит от качества и свежести сбора. Для тем, где нужен серьёзный разбор, вести сбор по скиллу `deep-research` — там четыре фазы и работа с разными типами свидетельств. Ниже минимально достаточный вариант.

### Поиск

Инструменты: `web_search` для поиска, `read` по URL для чтения статьи целиком, `browser` для страниц с JS или авторизацией — учитывать, что `browser` доступен главному агенту, а делегированному субагенту-разведчику нет, поэтому такие источники читать самому. Текущую дату брать из системного контекста (строка `Today:`), а не из памяти модели — иначе запросы уйдут в прошлый год.

```
# Новости и события
«<тема> новости <месяц> <год>»
«<тема> что произошло за неделю»

# Тренды и разбор
«<тема> тренды <год>»
«<тема> экспертный разбор»
«<тема> отраслевой отчёт»

# Цифры
«<тема> статистика <год>»
«<тема> данные рынка»

# Инструменты и материалы
«<тема> новые инструменты <год>»
«<тема> open source релиз»
```

Операторы `web_search`: `site:`, `-site:`, `after:2026-01-01`, `before:`, `filetype:pdf`, `"точная фраза"`, `OR`.

### Критерии отбора

| Критерий | Что значит |
|---|---|
| **Свежесть** | материалы за последние 7–30 дней |
| **Авторитетность** | первоисточники, официальные анонсы, издания с репутацией |
| **Уникальность** | свежий угол или недоосвещённая история, а не то, что уже везде |
| **Релевантность** | каждый пункт очевидно связан с темой выпуска |
| **Применимость** | читатель может что-то с этим сделать |
| **Разнообразие** | смесь новостей, разбора, цифр и практических материалов |

Пять отличных материалов лучше пятнадцати посредственных.

### Чтение ключевых историй

Для главных материалов открывать источник целиком и вытаскивать пять вещей: факты (что, кто, когда), контекст (почему важно), конкретные цифры, цитаты экспертов или официальные формулировки, следствия для читателя.

Не пересказывать материалы за платным доступом, которые читатель не сможет открыть.

## Фаза 3. Письмо

### Шапка

```markdown
# <Название рассылки>

*<Подзаголовок> — <дата>*

<Одно предложение о том, что внутри>
```

### Как писать блоки

**Главные истории**

- **Заголовок** — ясный, с обещанием пользы, без желтизны.
- **Зацепка** — 1–2 предложения, после которых читателю становится не всё равно.
- **Тело** — 2–4 абзаца: факты и контекст.
- **Почему это важно** — один абзац, связывающий новость с миром читателя.
- **Ссылка на источник** — всегда.

**Коротко**

Жирный заголовок + 2–3 предложения + ссылка. Одна мысль на пункт. Читатель должен получить суть, не переходя по ссылке.

**Разбор и комментарий**

Авторская позиция, а не пересказ. Схема: наблюдение → контекст → следствие → по возможности применимый вывод. Каждое утверждение опирается на данные или источник.

### Стандарты

| Принцип | Как выполняется |
|---|---|
| **Сканируемость** | заголовки, выделение, списки, короткие абзацы |
| **Увлекательность** | начинать с самого интересного, а не по хронологии |
| **Сжатость** | каждое предложение оправдывает своё место, филлер вырезается |
| **Точность** | каждый факт со ссылкой, каждая цифра проверена |
| **Атрибуция** | источник указывается ссылкой внутри текста |
| **Человечность** | писать как знающий коллега, а не как пресс-релиз |

### Калибровка тона под аудиторию

Одна и та же мысль для разных читателей:

| Аудитория | Тон | Пример |
|---|---|---|
| **Техническая** | точность, термины без разжёвывания | «Новый API поддерживает gRPC-стриминг с обработкой backpressure через окна управления потоком» |
| **Руководители** | влияние на бизнес, итог первым | «Сделка даёт компании 40 % корпоративного сегмента и напрямую подрывает ценовую власть прежнего лидера» |
| **Широкая** | доступность, аналогии | «Представьте универсальный переводчик для данных: любое приложение говорит с любой базой, не изучая новый язык» |

### Язык выпуска

Рассылка пишется на языке аудитории. Для русскоязычной рассылки русскими должны быть и заголовки, и комментарий; в оригинале остаются названия продуктов, компаний и цитаты — с переводом рядом, если цитата важна для смысла.

## Фаза 4. Сборка и вычитка

### Подвал

```markdown
*<Название> — <что это за рассылка>.*
*<Как подписаться, поделиться или ответить>*

*Все источники указаны ссылками в тексте. Подборка и комментарий — авторские.*
```

### Чек-лист перед отправкой

- [ ] У каждого утверждения есть ссылка на источник — утверждений без источника нет
- [ ] Все ссылки рабочие
- [ ] Даты соответствуют реальной текущей дате
- [ ] Материалы свежие, в заявленном временном окне
- [ ] Нет дублей: каждая история встречается один раз
- [ ] Форматирование единообразно по всему выпуску
- [ ] Нет перекоса в один источник или одну точку зрения
- [ ] Объём соответствует заявленному
- [ ] Первые два предложения заставляют читать дальше
- [ ] Концовка запоминается или даёт что сделать
- [ ] Вычитано: без опечаток, битой разметки и обрубленных фраз

## Шаблон выпуска

```markdown
# <Название рассылки>

*<Подзаголовок> — <дата>*

*В этом выпуске: <тема 1>, <тема 2> и <тема 3>.*

## От редактора

<Вступление на 2–4 предложения: чем этот выпуск отличается от прошлого, какая мысль связывает материалы. В ежедневной сводке и брифинге блок опускается — там сразу идёт главное.>

## Главное

### <Заголовок>

<Зацепка: почему это важно, 1–2 предложения.>

<Тело: 2–4 абзаца — факты, контекст, следствия.>

**Почему это важно:** <один абзац о влиянии на читателя.>

[Источник: <издание>](URL)

### <Заголовок 2>

<Та же структура.>

## Тренды и разбор

### <Название тренда>

<Авторский комментарий, опирающийся на собранные данные.>

<Ключевые цифры — списком или короткой таблицей.>

**Вывод:** <одно предложение.>

## Коротко

- **<Заголовок>** — <2–3 предложения с главной мыслью.> [источник](URL)
- **<Заголовок>** — <2–3 предложения.> [источник](URL)
- **<Заголовок>** — <2–3 предложения.> [источник](URL)

## Инструменты и материалы

- **<Название>** — <что делает и чем полезно.> [ссылка](URL)
- **<Название>** — <описание.> [ссылка](URL)

## И последнее

<Закрывающая мысль, цитата или взгляд вперёд.>

*<Название> собирает главное по теме «<тема>».*
*Было полезно — перешлите коллеге.*
```

## Настройка под тип рассылки

| Тип | Эмодзи | Секции | Тон |
|---|---|---|---|
| **Технологическая** | умеренно, только в заголовках секций | Главное, Разбор, Коротко, Open source, Инструменты | технично-разговорный |
| **Деловая и финансовая** | минимум или совсем без | Рынок, Сделки, Компании, Цифры, Прогноз | профессионально-аналитический |
| **Отраслевая** | умеренно | Регулирование, Данные рынка, Инновации, Кадровые движения, События | экспертно-авторитетный |
| **Креативная и маркетинговая** | свободно | Кампания выпуска, Тренды, Вирусное за неделю, Инструменты, Вдохновение | энергично-профессиональный |

## Где сохранять выпуск

По конвенции vault дайджест относится к ежедневному и архивному потоку, а не к evergreen-знанию:

- Регулярный выпуск — `Ежедневник/YYYY-MM-DD.md` либо отдельным файлом рядом с дневниковыми дайджестами.
- Рассылка для проекта — в каталог проекта в `Проекты/`, со ссылкой из файла проекта.
- Отдельной заметкой в `База знаний/` выпуск оформляется только если в нём есть самостоятельный разбор, который будет нужен позже; тогда добавляется frontmatter и запись в `База знаний/_Поисковый_индекс.md`.

Путь сохранения назвать в ответе.

## Замечания

- Для серии рассылок структуру держать неизменной: читатель привыкает к порядку блоков.
- Доверие строится на прозрачной атрибуции — источник указывается всегда, даже когда мысль кажется общеизвестной.
- Если пользователь дал конкретные ссылки, они идут в выпуск вместе с найденными, а не вместо них.
- Ценность должна быть в самих кратких изложениях: выпуск полезен, даже если читатель не перешёл ни по одной ссылке.
